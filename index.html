Three different things, on one site

This project mixes working code, untested-at-scale governance mechanisms, and a normative political argument. Conflating them is how a research prototype ends up sounding like a finished claim about how societies should be run. Here's the split, and where each lives:

Status words used across this site mean specific things, not vibes:

Implemented Exercised internally Replicated internally Independently reproduced Proposed Blocked Superseded Falsified
Implemented infrastructure

Implemented code with unit-test coverage

Holochain hApp architecture across 18 clusters (see Architecture below), three experimental economic mechanisms implemented in code, DID-based identity, and a bridge protocol for cross-cluster calls.

  • Builds and has unit tests today — Implemented
  • A minority of clusters have real multi-agent (Tryorama/sweettest) coverage — Partial
  • Two areas have working user-facing application prototypes: Pulse and Praxis — see below
Experimental governance mechanisms

Designed, partly built, unproven

The participation profile and vote-weight-by-tier design, detailed on the Governance page, are being tested in code — not a validated model of legitimate governance.

  • Never governed a real community or made a binding decision for real people
  • Open, unresolved risks — full register on the Risks page
  • Presented for scrutiny, not as a finished answer
Normative philosophical proposal

An argument, not a finding

The Philosophy page holds this project's own political and philosophical position — offered for debate, not as evidence.

  • Not empirically established, and not claimed to be
  • You're meant to disagree with parts of it if you do
  • Kept on its own page so agreeing with the code doesn't require agreeing with the politics

Three blockers to any real deployment

The short version — full register with severity, owner, and evidence links is on the Risks page.

  1. No appeals or contestability process for participation-profile decisions. Blocks any deployment that affects real people.
  2. Guardian emergency authority is unimplemented and governance-blocked — no approved scope, quorum, duration, audit, or revocation mechanism exists.
  3. A known authorization-binding defect class is still open in some clusters (fixed in most, tracked cluster-by-cluster) — see Security status.
